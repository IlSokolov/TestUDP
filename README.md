# UDP Client-Server

Реализованы UDP-клиент и UDP-сервер на C++17 с использованием Winsock2. Реализован обмен сообщениями INIT, INIT_ACK, CONFIRM и CONFIRM_ACK, вычисление общего секрета и проверка HMAC-SHA256.

Проверены успешный обмен, обработка некорректных сообщений, отклонение повторного `exchange_id`, проверка неправильного HMAC и тайм-аут. Также проверена очистка секретных и случайных данных после успешного обмена и истечения времени ожидания.

Для очистки памяти используется функция `secure_zero`, реализованная на чистом C в отдельных файлах `.c/.h`. В функции применяются записи через указатель `volatile unsigned char`, что предотвращает удаление операций обнуления оптимизатором компилятора.

Для `exchange_id` используется порядок байтов Big Endian. Одинаковое четырёхбайтовое представление применяется при включении идентификатора во входные данные SHA-256 и HMAC-SHA256 на обеих сторонах.

## Сборка и запуск

Решение содержит два отдельных проекта Visual Studio: `Client` и `Server`. Для сборки требуется Visual Studio 2022 с поддержкой C++17 и библиотека `Ws2_32.lib`.

Сначала запускается `Server`, затем `Client`. По умолчанию клиент подключается к `127.0.0.1:8080`.

## Используемые криптографические функции

Для SHA-256 и HMAC-SHA256 используется реализация из [hmac_sha256](https://github.com/h5p9sl/hmac_sha256).

Для вычисления SHA-256 используется функция `Sha256Calculate()`, принимающая указатель на исходные данные, их размер и указатель на структуру результата `SHA256_HASH`. Результат записывается в виде 32 байт в поле `bytes`.

Для вычисления HMAC используется функция `hmac_sha256()`, принимающая ключ, его длину, исходные данные, их длину и буфер для результата. Функция возвращает количество записанных байтов.

SHA-256 обрабатывает сообщение блоками по 512 бит с использованием 64 раундов преобразования внутреннего состояния. HMAC-SHA256 выполняет два последовательных хеширования с использованием ключа и констант `ipad` и `opad`: сначала внутреннее, затем внешнее.
